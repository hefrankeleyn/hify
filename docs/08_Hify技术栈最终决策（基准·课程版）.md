# Hify 技术栈最终决策（基准版 · 依据课程）

> 📌 本文档为 **Hify 技术栈的最终决策基准（source of truth）**，以课程给出的方案为准。
> 实操以此为准：`06_Hify技术选型对比.md`（推荐 FastAPI）与 `07_SpringBoot-vs-FastAPI工程化能力.md` 为作者的独立分析/过程记录，**如与本文档冲突，以本文档为准**。
> 整理日期：2026-07-12

---

## 一、最终决策

**选 Spring Boot + Vue，不拆分独立的 Python 服务。**

### 最终技术栈

| 层 | 选型 | 理由 |
|----|------|------|
| **后端** | Spring Boot 3.x + MyBatis-Plus + MySQL 8.x + Redis 7.x | 工程化成熟，一个人能快速交付完整系统。 |
| **前端** | Vue 3 + TypeScript + Element Plus | 管理后台场景成熟度最高。 |
| **容器化** | Docker + Docker Compose | 最稳、最简。 |

---

## 二、决策理由（三点）

1. **一个人开发，效率第一 → 选最熟的栈。**
   开发者对 Spring Boot + Vue 这套栈最熟悉，单人开发时「熟练度」直接决定交付速度，是第一优先级。

2. **Java 的 AI SDK 够用，不依赖 Python 专属框架。**
   - OpenAI、Claude 都有官方/成熟的 **Java SDK**，模型调用没问题。
   - RAG 的向量化**直接调 API 即可**，不必依赖 LangChain 这类 Python 生态框架。
   - 结论：AI 能力用 Java 栈完全可以承载，无需为此引入第二套语言。

3. **一个人一套技术栈，不分裂。**
   单人维护，最怕技术栈分裂（Java + Python 两套语言、两套工具链、两套部署）。统一到一套栈，认知负担和运维复杂度都最低。

---

## 三、决策哲学（核心）

> **技术选型不是选「最好的技术」，是选「最匹配当前约束的技术」。**

- AI 生态在 Python 更强，这个劣势**确实存在**——课程没有回避。
- 但对本项目而言，**「工程化能力 + 技术栈统一性」带来的优势，大于「AI 生态」的劣势**。
- 权衡的落点由**当前约束**（一个人、最熟 Java、本地部署、事务/工程化要求）决定，而非技术本身的绝对先进性。

---

## 四、与作者独立分析的对账（为什么结论从 FastAPI 变成 Spring Boot）

作者此前在 `06` 推荐 FastAPI、在 `07` 承认「Spring 工程化更强但本项目影响有限」。课程结论相反，**分歧不在于谁算错了，而在于一个决定性变量**：

| 关键变量 | 作者分析（06/07）时的状态 | 课程决策的取值 | 影响 |
|----------|--------------------------|----------------|------|
| **开发者最熟的栈** | 未知（`06`/`07` 均明确标注「若你是资深 Java 工程师，此为额外一票给 Spring」） | **最熟 Spring Boot + Vue** | 决定性地倒向 Spring |
| AI 生态权重 | 权重拉满 → 倾向 Python | 承认劣势，但让位于工程化+统一性 | 权重下调 |
| 事务/工程化 | 认为本项目事务复杂度中低、影响有限 | 视工程化成熟为核心优势 | 权重上调 |

**结论**：
- 作者的推荐是**有前提的条件推荐**，并主动标注了「个人熟练度是缺失变量」。课程补上了这个变量（最熟 Java），推荐随之翻转——这**印证**了作者的判断框架，而非推翻。
- 也印证了本项目一路的方法论：**技术选型要把「个人熟练度、技术栈统一性」这类约束代入，而不是只看某维度（AI 生态）的绝对强弱。** 生态引力是一个重要因素，但不是唯一因素。

## 五、与既有基准（功能取舍）的一致性检查

- `05_Hify功能取舍（基准·极客时间课程版）.md` 中「MCP 工具接入」仍然成立：**MCP 有 Java SDK**，用 Spring Boot 一样能接入 MCP 工具生态，与本决策不冲突。
- 「不依赖 LangChain」指的是不引入 Python 专属的编排框架，而非放弃 RAG/工具能力——RAG 向量化调 API、工具走 MCP，均可在 Java 栈内实现。
- 因此：**功能取舍基准（05）+ 技术栈基准（本文档 08）二者自洽**，可直接作为 Hify 的实施依据。

### 步骤 12：案例⑨——容量规划（QPS/缓存/运维）

- **用户原话**：「Hify 是一个 AI Agent 平台，Docker Compose 本地部署，目标 20-50 人同时在线，主要压力在对话接口（流式 SSE）。帮我估算 QPS、建议缓存策略、列出需要提前考虑的运维事项。」
- **任务**：估算 QPS、给缓存策略、列运维 checklist。
- **执行过程**：
  1. 先纠偏指标：流式 SSE 场景 QPS 会误导人，真正要算「并发连接数」——用 Little's Law 估出并发 SSE 峰值≈在线人数（~50）。
  2. 指出真正瓶颈是「本地模型的并发生成能力」，而非 Spring/MySQL。
  3. 缓存策略按收益排序（配置/会话/Embedding/检索/响应/限流）+ 版本化 key + 失效策略。
  4. 运维 checklist 按 SSE连接/容错/资源部署/可观测/数据安全 分组；给起步配置建议值。
- **产出**：`docs/09_Hify容量规划与运维.md`。
- **方法论提炼**：见方法论文档新增条目——「用对的指标：别拿 QPS 套流式长连接系统」。
- **时间**：2026-07-12
